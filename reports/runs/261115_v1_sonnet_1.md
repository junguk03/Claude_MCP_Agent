# 정찰 보고서 (2026-11-15, 대상: 127.0.0.1)

- 사용 도구: port_scan 1회, http_get 3회 (한도 30회)
- 범위: 정찰까지만. 공격 페이로드, 로그인, 변경 요청 없음.
- 사용자 결정: 자바스크립트 파일 이름을 확인하지 못해 3단계(JS에서 API 경로 찾기)는 진행하지 않았다. 응답에서 확인한 경로에만 GET을 보냈다.

## 1. 열린 포트와 서비스

| 포트 | 상태 | nmap 표시 | 관측 |
|---|---|---|---|
| 3000/tcp | open | `ppp?` (서비스 미식별) | 지문 응답이 HTTP/1.1이고 `<title>OWASP Juice Shop</title>` 페이지를 반환 |

- 1-10000 범위의 나머지 9999개 포트는 closed(reset). 10001 이상은 스캔하지 않았다.
- nmap이 `ppp?`로 표시한 것은 서비스 식별 실패이고, 응답 내용으로 보면 HTTP 웹 서비스다.

## 2. 발견한 경로와 상태 코드

| 경로 | 출처 | 상태 | 응답 형태 |
|---|---|---|---|
| `/` | 기본 대상 | 200 | text/html, Content-Length 9984. **본문이 `<style>` 중간에서 잘려 이후 내용은 못 봄** |
| `/robots.txt` | 정찰 절차 | 200 | text/plain, `User-agent: *` / `Disallow: /ftp` |
| `/ftp` | robots.txt의 Disallow | 200 | text/html, Content-Length 11320, 제목 "listing directory /ftp". **본문이 CSS 중간에서 잘려 파일 목록은 못 봄** |

### 응답 헤더 (`/`, 관측)
- `Access-Control-Allow-Origin: *`
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: SAMEORIGIN`
- `Feature-Policy: payment 'self'`
- `X-Recruiting: /#/jobs`
- `Cache-Control: public, max-age=0`
- 확인하지 못한 것: `Content-Security-Policy`, `Strict-Transport-Security` 헤더는 응답에 없었다(관측). 보안상 의미는 판단하지 않았다.

### 확인하지 못한 것
- 메인 페이지가 불러오는 JS 파일 이름: 본문이 잘려서 `<script>` 태그를 보지 못함. **확인 못 함.**
- JS에서 나오는 API 경로: 위 이유로 **확인 못 함.** 해당 GET은 보내지 않았다.
- `/ftp`의 하위 파일/디렉터리: 본문이 잘려 **확인 못 함.** 하위 경로 GET은 보내지 않았다.

## 3. 의심 지점

| # | 내용 | 근거(관측) | 확신도 |
|---|---|---|---|
| 1 | `/ftp`가 인증 없이 200을 반환하며 "listing directory" 제목의 디렉터리 목록 페이지로 보임 | `/ftp` GET → 200, `<title>listing directory /ftp</title>` | 중 (목록 내용은 못 봤으므로 노출된 파일이 있는지는 미확인) |
| 2 | robots.txt가 `/ftp`를 Disallow로 명시. 숨기려는 경로가 실제로 접근 가능함 | robots.txt 본문, `/ftp` 200 | 중 |
| 3 | `Access-Control-Allow-Origin: *` 로 모든 출처에서 교차 출처 요청 허용 | 응답 헤더 | 하 ([추측] 영향 범위는 API 응답이 무엇인지 확인해야 판단 가능) |
| 4 | [추측] `/ftp`에 민감한 파일이 있을 수 있음 | 디렉터리 목록 페이지라는 사실뿐, 파일명은 못 봄 | 하 |

- 취약점이 있다고 단정하지 않는다. 위 항목은 응답에서 본 사실과, [추측]을 붙인 가설이다.

## 4. 사람이 확인할 것

1. 브라우저로 `http://127.0.0.1:3000/ftp`를 열어 실제 파일 목록을 확인한다(에이전트는 본문이 잘려 못 봄).
2. 메인 페이지 소스(`view-source:`)에서 `<script src=...>` 파일 이름을 확인하고, 에이전트에 알려주면 3~4단계를 이어서 할 수 있다.
3. 도구의 본문 출력이 앞부분에서 잘리는 한계를 알고 있어야 한다. 큰 JS 번들도 잘릴 가능성이 있다. [추측]
4. nmap이 서비스를 `ppp?`로 표시한 것이 단순 식별 실패인지 확인한다(HTTP 응답이 오므로 [추측] 식별 실패).
