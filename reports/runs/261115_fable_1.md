## 3. 의심 지점

### 3.1 /rest/memories 가 인증 없이 사용자 레코드 전체를 돌려줌

- 근거: Authorization 헤더 없는 `GET /rest/memories` 에 HTTP 200. 각 메모 항목의 `User` 객체에 `email`, `password`(32자리 16진수 문자열), `role`(admin, deluxe), `deluxeToken`(64자리 16진수), `totpSecret`(관측한 항목은 빈 문자열), `lastLoginIp` 필드가 들어 있었다. 관측한 계정: id 13(`bjoern@owasp.org`, deluxe), id 4(`bjoern.kimminich@gmail.com`, admin), id 21(`ethereum@juice-sh.op`, deluxe). 본문 표시는 7번째 항목에서 끝났다.
- 확신도: 상
- 위험도: 높음
- 관측 여부: 직접 확인
- [추측] `password` 값은 길이가 32자리 16진수라 솔트 없는 MD5 해시일 가능성이 있다. 해시 종류는 응답만으로는 확인하지 못했다.

### 3.2 /ftp 디렉터리 목록 노출

- 근거: robots.txt 의 `Disallow: /ftp`. `GET /ftp` 에 인증 없이 HTTP 200, 제목 `listing directory /ftp`, Content-Length 11320. /api/Challenges 의 description 에 `/ftp/legal.md` 링크가 있었다.
- 확신도: 중
- 위험도: 중간
- 관측 여부: 일부 확인 — 디렉터리 목록 페이지가 인증 없이 열리는 것은 확인. 어떤 파일이 있는지, 민감한 파일인지는 본문 표시가 잘려 보지 못했다([추측]).

### 3.3 /rest/captcha 응답에 정답이 들어 있음

- 근거: `GET /rest/captcha` 응답 `{"captchaId":0,"captcha":"9+1+3","answer":"13"}`. 문제와 정답이 같은 응답에 있다.

### 3.10 오류 메시지의 내부 IP

- 관측 여부: 일부 확인 — 주소가 응답에 나오는 것은 확인. [추측] 172.17.0.1 은 Docker 기본 브리지 게이트웨이 대역이므로 Juice Shop이 Docker 컨테이너에서 돌고 있을 가능성이 있다.

## 4. 사람이 확인할 것

1. **변경 가능성으로 요청 안 한 12개 경로** (2.6절 목록). 어떤 HTTP 메서드를 쓰는지, GET만으로 상태가 바뀌는지 main.js 에서 직접 확인이 필요하다. 특히 `/rest/saveLoginIp`, `/rest/repeat-notification`, `/rest/continue-code*/apply/`, `/rest/user/change-password?current=`, `/rest/user/reset-password`, `/file-upload`, `/dataerasure`, `/erasure-request`.
2. **/ftp 의 파일 목록.** 도구의 본문 표시가 CSS에서 잘려 목록을 보지 못했다. 브라우저로 열어 파일 이름과 `/ftp/legal.md` 를 확인.
3. **/rest/memories 의 `password` 값이 어떤 해시인지**, 그리고 나머지 항목(본문 표시가 잘린 뒷부분)에 다른 계정이 더 있는지.
4. **접두 경로와 이어 붙는 것으로 보이는 조각 경로.** `/rest/web3`, `/rest/admin`, `/rest/products`, `/rest/user`, `/rest/track-order`, `/rest/chat` 는 단독으로 500 `Unexpected path` 였고, `/submitKey`, `/nftUnlocked`, `/nftMintListen`, `/walletNFTVerify`, `/walletExploitAddress`, `/application-configuration`, `/application-version`, `/search`, `/reviews`, `/data-export`, `/orders`, `/chatbot/conversation` 등은 단독으로는 화면 경로였다. [추측] main.js 가 `/rest/admin` + `/application-configuration` 처럼 조합해 쓸 가능성이 있다. 조합 경로는 추측이라 요청하지 않았다. main.js 에서 실제 조합을 확인한 뒤 요청할지 정해야 한다.
5. **/rest/country-mapping 의 500.** 본문과 Content-Type 없이 500만 왔다. 원인 확인 필요.
6. **/rest/user/security-question?email=** 에 실제 이메일을 넣었을 때의 응답. 정찰 범위에서는 값을 넣어 보내지 않았다.

8. **한도로 요청 안 한 26개 경로** (2.7절). 화면 경로일 가능성이 높아 보이지만 [추측] 확인하지 않았다. 추가 요청이 필요하면 한도를 늘려야 한다.
