## 3. 의심 지점

### 3-1. /rest/memories가 인증 없이 사용자 정보 전체를 돌려줌
- 근거: 인증 헤더 없이 GET → 200. 각 항목에 `User` 객체가 중첩되어 있고, 필드에 `email`, `password`(32자리 16진 문자열), `role`(admin, deluxe), `deluxeToken`, `totpSecret`, `lastLoginIp`, `isActive`가 보였다. 본문이 중간에서 끊겨 전체 항목 수와 전체 사용자 수는 모른다.
- 확신도: 상
- 위험도: 높음
- 관측 여부: 일부 확인. 인증 없이 200이 오고 해시, 토큰 필드가 응답에 들어 있는 것은 직접 확인했다. 해시가 MD5라는 것과 토큰이 실제로 쓸 수 있다는 것은 추측이다. [추측] 32자리 길이만 보고 MD5로 짐작했고 검증하지 않았다.
- 값은 이 보고서에 옮기지 않았다.

### 3-2. 오류 응답이 내부 구조를 드러냄
- 근거: 500 응답 여러 개(/rest/web3, /rest/admin, /rest/products 등)의 HTML에 `/juice-shop/build/routes/angular.js`, `/juice-shop/node_modules/express/...` 같은 서버 파일 경로와 `Express ^4.22.1` 문구가 있다. /rest/user/security-question은 `WHERE parameter "email" has invalid "undefined" value`와 `SQLiteQueryGenerator`, `SecurityAnswer.findAll` 스택을 돌려줬다. /api/Addresss, /api/Cards, /rest/wallet/balance는 `Cannot read properties of undefined (reading 'data')`를 JSON 오류 메시지로 돌려줬다.
- 확신도: 상 (정보 노출 자체는 응답에 그대로 있음)
- 위험도: 중간
- 관측 여부: 직접 확인. 이 응답으로 SQL 인젝션이 가능하다고 확인한 것은 없다. [추측] 쿼리 파라미터가 DB 조건에 그대로 쓰인다는 정도까지만 짐작할 수 있고, 검증하지 않았다.

### 3-3. /api/Feedbacks가 인증 없이 열려 있고 민감해 보이는 문장이 들어 있음
- 근거: 인증 없이 200. 8건 중 한 건의 comment에 지갑 주소가 아닌 12개 단어 문구(복구 구문으로 보이는 형태)와 NFT 요청 문장이 있고, 이메일 일부가 마스킹되어 있다(`***ereum@juice-sh.op` 형태).
- 확신도: 중
- 위험도: 중간
- 관측 여부: 일부 확인. 응답에 해당 문장이 있는 것은 직접 확인했다. 그 문구가 실제 지갑의 복구 구문인지는 추측이다. [추측] 실습 앱의 시드 데이터일 가능성이 높다.
- 문구는 이 보고서에 옮기지 않았다.

### 3-4. /rest/captcha 응답에 정답이 같이 들어 있음
- 근거: 200 응답 `{"captchaId":1,"captcha":"3+10+5","answer":"18"}`. 문제와 정답이 같은 응답에 있다.
- 확신도: 상
- 위험도: 낮음
- 관측 여부: 직접 확인. 이 캡차가 어떤 기능(피드백 등)에 쓰이는지는 확인하지 않았다.

### 3-5. /api/Challenges, /api/Hints가 인증 없이 열림
- 근거: 둘 다 200, 각각 69,075바이트와 99,623바이트. 챌린지 이름, 카테고리, 설명, 난이도, 힌트 텍스트가 보였다. /api/Challenges 설명에 /ftp/legal.md 링크 문구도 있다. 본문은 앞부분만 확인했다.
- 확신도: 중 (취약점이라기보다 앱 설계상 공개 데이터일 가능성)
- 위험도: 참고
- 관측 여부: 일부 확인. 인증 없이 열려 있고 내용이 있는 것은 직접 확인했다. [추측] 학습용 앱의 의도된 동작일 수 있다.

### 3-6. /api/ 엔드포인트의 인증 처리가 일관되지 않음
- 근거: /api/Users, /api/BasketItems, /api/SecurityAnswers, /api/Complaints는 401과 "No Authorization header was found" HTML을 돌려주고, /api/Addresss, /api/Cards는 401이지만 JSON에 JS 내부 오류 메시지가 들어 있다. /api/Products, /api/Quantitys, /api/SecurityQuestions, /api/Deliverys, /api/Feedbacks는 인증 없이 200이다.
- 확신도: 하 (인증이 필요한 것과 필요 없는 것이 나뉘는 것 자체는 정상일 수 있음)
- 위험도: 참고
- 관측 여부: 직접 확인. 어느 쪽이 의도된 것인지는 모른다.

### 3-7. /rest/order-history, /profile이 "Blocked illegal activity by ::ffff:172.17.0.1"를 돌려줌
- 근거: 두 경로 모두 500. 오류 메시지에 클라이언트 주소로 `::ffff:172.17.0.1`이 보인다(orderHistory.js:55, userProfile.js:69).
- 확신도: 하
- 위험도: 참고
- 관측 여부: 일부 확인. 오류 메시지와 파일 위치는 직접 확인했다. [추측] 인증 정보가 없을 때 코드가 던지는 오류 문구일 가능성이 있고, 왜 이 문구가 나오는지는 확인하지 않았다. 172.17.0.1은 Docker 기본 브리지 주소 대역으로 보인다.

### 3-8. 응답 헤더
- 근거: 모든 응답에 `Access-Control-Allow-Origin: *`. 메인 페이지와 robots.txt 응답에서 CSP, HSTS 헤더는 보이지 않았다. `X-Recruiting: /#/jobs` 헤더가 있다.
- 확신도: 하
- 위험도: 참고
- 관측 여부: 직접 확인 (헤더 존재/부재). 실제 악용 가능성은 확인하지 않았다.

### 3-9. robots.txt가 /ftp를 Disallow로 알려줌
- 근거: /robots.txt 응답 `Disallow: /ftp`.
- 확신도: 중
- 위험도: 참고
- 관측 여부: 일부 확인. 항목이 robots.txt에 있는 것은 직접 확인했다. /ftp에 실제로 무엇이 있는지는 요청하지 않았다. [추측] 숨기고 싶은 파일 목록이 있을 수 있다.

## 4. 사람이 확인할 것

1. **/rest/memories**: 인증 없이 사용자 객체(해시, deluxeToken, totpSecret 필드)가 나오는 것을 직접 확인해 보기. 전체 항목 수, 로그인 상태에서 응답이 달라지는지.
2. **변경 가능성으로 요청하지 않은 경로 10개** (2-4 목록): 어떤 HTTP 메서드를 받는지, 인증이 필요한지. 직접 요청하지 말고 코드나 문서에서 먼저 확인.
3. **/ftp** (robots.txt Disallow): 접근 가능 여부와 내용.
4. **허용 대상 밖 포트 37183, 45469, 46737**: 어떤 프로세스인지(`ss -ltnp` 등 로컬 확인). 에이전트는 요청하지 않았다.
5. **/rest/user/security-question**: `email` 쿼리를 어떻게 처리하는지. 이번에는 쿼리 없이 요청해서 `undefined` 오류가 났다.
6. **본문이 잘린 응답 5개** (/rest/memories, /api/Challenges, /api/Products, /api/Quantitys, /api/Hints): 전체 내용과 항목 수.
7. **/rest/order-history, /profile**의 "Blocked illegal activity" 오류가 나는 조건.
8. **/engine.io, /socket.io**: 쿼리 없는 GET이 메인 페이지를 돌려준 이유.
9. **한도 때문에 요청하지 못한 화면 경로 27개** (2-5 목록): 다음 정찰에서 이어서 요청할지 결정.
10. /api/Feedbacks의 12단어 문구가 시드 데이터인지, 다른 곳에서 쓰이는 값인지.
