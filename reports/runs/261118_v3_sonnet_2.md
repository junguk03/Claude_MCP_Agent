## 3. 의심 지점

### 3-1. /rest/memories: 인증 헤더 없이 사용자 정보 필드가 응답에 포함됨
- 근거: 인증 헤더 없는 GET이 200을 받았다. 보이는 앞부분에 사진 항목마다 `User` 객체가 붙어 있었다. 필드는 email, password(32자리 16진수 문자열), role, deluxeToken, totpSecret, lastLoginIp, profileImage다. 값은 이 보고서에 옮기지 않았다.
- 확신도: 상
- 위험도: 높음
- 관측 여부: 일부 확인. 확인한 것은 필드의 존재와 인증 없는 200 응답이다. 추측은 두 가지다. password 값이 MD5 같은 해시인지, 이 값들로 실제 인증이 가능한지는 확인하지 않았다. 본문이 잘려 전체 사용자 수도 모른다.

### 3-2. /api/Feedbacks: 공개 응답 안에 지갑 시드 문구처럼 보이는 문자열
- 근거: 인증 없이 200. id 4번 comment에 영어 단어 12개가 따옴표 안에 나열돼 있고 "wallet"이 언급된다. 작성자 이메일은 일부 마스킹돼 있다. 문구는 옮기지 않았다.
- 확신도: 중
- 위험도: 중간
- 관측 여부: 일부 확인. 해당 문자열이 응답에 있는 것은 확인했다. [추측] 실제 지갑 시드 문구인지, 유효한지는 확인하지 않았다.

### 3-3. 상세 오류 페이지 노출 (스택 트레이스, 내부 경로, 내부 오류 메시지)

- 확신도: 상 (정보 노출로서)
- 위험도: 낮음
- 관측 여부: 직접 확인. 노출된 내용(프레임워크 버전, 파일 경로, ORM/DB 종류 단서)은 응답에서 확인했다. security-question의 쿼리 오류가 입력 검증 부족을 뜻하는지, 주입이 가능한지는 확인하지 않았다. [추측] 주입 가능성은 단정하지 않는다.

### 3-4. /rest/captcha: 응답에 CAPTCHA 정답이 함께 들어 있음
- 근거: 200 응답 JSON에 `captcha`(식)와 `answer`(값)가 같이 있다.
- 확신도: 상 (정답이 응답에 있다는 점)

- 관측 여부: 일부 확인. 응답에 정답이 들어 있는 것은 직접 확인했다. [추측] 이 CAPTCHA가 어떤 기능을 보호하는지, 우회가 실제로 되는지는 확인하지 않았다.

### 3-5. /ftp: robots.txt가 숨기려는 경로에서 디렉터리 목록 페이지가 열림
- 근거: robots.txt에 `Disallow: /ftp`가 있고, /ftp가 200으로 "listing directory /ftp" 페이지를 돌려줬다.
- 확신도: 중
- 위험도: 중간
- 관측 여부: 일부 확인. 목록 페이지가 열리는 것은 확인했다. 본문이 잘려 파일 이름을 못 봤다. [추측] 민감한 파일이 있는지는 알 수 없다.

### 3-6. /rest/order-history, /profile: "Blocked illegal activity" 오류와 클라이언트 IP 노출
- 근거: 두 경로 모두 500이고 메시지가 `Blocked illegal activity by ::ffff:172.17.0.1`이다. 스택 첫 줄은 각각 orderHistory.js:55, userProfile.js:69다.
- 확신도: 하
- 위험도: 참고
- 관측 여부: 일부 확인. 메시지와 IP 표기는 확인했다. [추측] 인증 없는 요청을 막는 서버 코드일 수 있고, 172.17.0.1은 Docker 기본 브리지 주소로 보인다. 어느 쪽도 확인하지 않았다.

### 3-7. 인증 없이 200으로 열린 /api/ 목록과 데이터
- 근거: /api/Feedbacks, /api/Challenges, /api/Products, /api/Quantitys, /api/SecurityQuestions, /api/Deliverys, /api/Hints가 인증 헤더 없이 200이다. /api/Quantitys에는 재고 수량과 limitPerUser가, /api/Challenges와 /api/Hints에는 챌린지 설명, 해결 여부, 힌트가 있다. /rest/continue-code도 인증 없이 코드 값을 준다.
- 확신도: 하
- 위험도: 참고
- 관측 여부: 일부 확인. 인증 없이 200이 오는 것은 확인했다. [추측] 상품과 질문 목록은 상점 기능상 공개일 수 있고, 챌린지와 힌트는 학습용 앱 특성일 수 있다. 의도된 공개인지는 판단하지 않았다.

## 4. 사람이 확인할 것

1. **변경 가능성으로 요청 안 함 12개 경로** (2-5절 목록). 직접 확인할 때 데이터가 바뀔 수 있으니 주의.
2. **/ftp 파일 목록.** 브라우저로 열어 어떤 파일이 있는지 확인. 파일을 받는 요청은 이번 정찰 범위 밖이라 하지 않았다.
3. **/rest/memories 전체 응답.** 본문이 잘려서 어떤 사용자가 몇 명 나오는지 모른다.
4. **포트 42201, 45159의 정체.** 특히 45159는 nmap 지문 응답에 로컬 작업 디렉터리가 담긴 개발 오류 페이지가 있었다. 이 프로젝트와 관련된 프로세스인지 확인.
5. **/rest/user/security-question의 오류 원인.** `email` 값이 없을 때 쿼리 오류가 난다. 이 입력이 어떻게 처리되는지는 직접 따져볼 부분이다.
6. **/rest/ 아래 GET에 "Unexpected path"를 돌려준 경로** (web3, user/login, admin, track-order, products, user, chat). GET이 아닌 다른 메서드에서 동작하는지는 확인하지 않았다.
7. **main.js 외 JS 파일의 api_paths가 0개.** [추측] 메인 페이지에 링크되지 않은 지연 로딩 chunk가 더 있을 수 있다. 절차상 메인 페이지에 링크된 파일만 확인했다.
