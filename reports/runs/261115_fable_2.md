## 3. 의심 지점

### 3.1 /rest/memories가 인증 없이 사용자 레코드 전체를 돌려줌
- 근거: 인증 헤더 없는 `GET /rest/memories`가 200. 각 항목의 `User` 객체에 `email`, `password`(32자리 16진 문자열), `role`(admin, deluxe), `deluxeToken`, `totpSecret`, `lastLoginIp` 필드가 들어 있었다. 본 계정: bjoern@owasp.org(deluxe), bjoern.kimminich@gmail.com(admin), ethereum@juice-sh.op(deluxe).
- 확신도: 상
- 위험도: 높음
- 관측 여부: 일부 확인 — 필드와 값이 노출되는 것은 직접 확인. `password` 값이 솔트 없는 MD5 해시라는 것은 길이만 보고 한 `[추측]`이며, 해시 크래킹이나 로그인은 시도하지 않음.

### 3.2 /ftp 디렉터리 목록 노출
- 근거: robots.txt의 `Disallow: /ftp`, 그리고 `GET /ftp`가 200에 제목 `listing directory /ftp` (11320바이트). /api/Challenges 응답 안에도 `/ftp/legal.md` 링크가 있었다.
- 확신도: 상 (디렉터리 목록 기능이 켜져 있다는 점)
- 위험도: 중간
- 관측 여부: 일부 확인 — 목록 페이지가 인증 없이 열리는 것은 직접 확인. 본문이 CSS 부분에서 잘려 파일 이름은 보지 못했고, 민감한 파일이 있는지는 `[추측]`.

### 3.3 /rest/captcha 응답에 정답이 들어 있음
- 근거: `GET /rest/captcha` → `{"captchaId":0,"captcha":"8-5-6","answer":"-3"}`. 문제와 정답이 같은 응답에 있다.
- 확신도: 상
- 위험도: 중간
- 관측 여부: 일부 확인 — 정답 필드 노출은 직접 확인. 이 값으로 CAPTCHA 검증을 통과할 수 있는지는 제출하지 않아 `[추측]`.

### 3.4 오류 페이지의 스택 트레이스와 내부 정보 노출
- 근거: 500 응답 다수(/rest/web3, /rest/user/login, /rest/admin, /rest/track-order, /rest/products, /rest/user, /rest/chat, /rest/order-history, /rest/user/security-question, /profile)가 `OWASP Juice Shop (Express ^4.22.1)` 표기와 서버 내부 경로(`/juice-shop/build/routes/angular.js:18`, `/juice-shop/build/lib/insecurity.js:218`, `/juice-shop/node_modules/sequelize/...`)를 포함. security-question 오류에서 `SQLiteQueryGenerator`, `SecurityAnswer.findAll`이 보임. order-history·profile 오류에 클라이언트 주소 `::ffff:172.17.0.1`이 찍힘.
- 확신도: 상
- 위험도: 낮음
- 관측 여부: 일부 확인 — 프레임워크·경로·ORM 이름 노출은 직접 확인. DB가 SQLite라는 것과 172.17.0.1로 미루어 Docker 컨테이너에서 돈다는 것은 `[추측]`.

### 3.5 /rest/user/security-question의 email 파라미터
- 근거: 파라미터 없이 요청하자 500 `WHERE parameter "email" has invalid "undefined" value`. 입력값이 DB 조회 조건으로 들어간다는 것을 오류 문구가 보여 준다. main.js에 `?email=` 형태로 쓰인다.
- 확신도: 중 (이메일로 사용자 존재 여부·보안 질문을 알아낼 수 있을 가능성)
- 위험도: 중간
- 관측 여부: 일부 확인 — 파라미터 없는 요청의 오류만 직접 확인. 실제 이메일을 넣었을 때의 응답과 사용자 열거 가능 여부는 요청하지 않아 `[추측]`. SQL 인젝션 여부는 판단할 근거가 없다.

### 3.6 /api/Feedbacks 인증 없이 조회, 댓글에 민감해 보이는 문자열
- 근거: `GET /api/Feedbacks` 200. id 4 댓글에 "/juicy-nft" 경로 언급과 따옴표로 묶인 영어 단어 12개가 있다. id 5, 6 댓글에 `<em>`, `<b>`, `<br />` HTML 태그가 그대로 저장돼 있다.
- 확신도: 중
- 위험도: 중간
- 관측 여부: 일부 확인 — 응답 내용은 직접 확인. 단어 12개가 지갑 시드 문구라는 것, 저장된 HTML이 화면에서 이스케이프 없이 렌더링된다는 것(XSS 가능성)은 `[추측]`.

### 3.7 /rest/continue-code 인증 없이 조회
- 근거: `GET /rest/continue-code` 200, `{"continueCode":"<60자>"}`. 짝이 되는 `/rest/continue-code/apply/` 경로가 main.js에 있다(요청 안 함).

- 위험도: 참고
- 관측 여부: 일부 확인 — 코드 조회는 직접 확인, 용도와 apply 동작은 `[추측]`.

### 3.8 /api/Challenges, /api/Hints, /api/Quantitys, /api/SecurityQuestions 인증 없이 조회
- 근거: 모두 인증 헤더 없이 200과 목록 JSON. 반면 /api/Users, /api/BasketItems, /api/SecurityAnswers, /api/Complaints는 401.
- 확신도: 하 (의도된 공개 데이터일 수 있음 `[추측]`)
- 위험도: 낮음 (재고 수량 `quantity` 노출)
- 관측 여부: 직접 확인

### 3.9 CORS 전체 허용과 보안 헤더 부재
- 근거: 모든 응답에 `Access-Control-Allow-Origin: *`. nmap의 OPTIONS 프로브에 `Access-Control-Allow-Methods: GET,HEAD,PUT,PATCH,POST,DELETE`. 메인 페이지 응답에 CSP·HSTS 헤더 없음.
- 확신도: 중
- 위험도: 낮음
- 관측 여부: 일부 확인 — 헤더 값은 직접 확인. 다른 출처에서 인증된 응답을 읽을 수 있는지는 `[추측]` (`Access-Control-Allow-Credentials` 헤더는 응답에 없었음).

### 3.10 401 응답의 내부 오류 문구와 일관되지 않은 인증 처리
- 근거: /api/Addresss, /api/Cards, /rest/wallet/balance는 401에 `Cannot read properties of undefined (reading 'data')`라는 JavaScript 런타임 오류 문구를 돌려줌. /rest/deluxe-membership은 인증 없이 400 `You are not eligible`, /rest/user/whoami는 200 `{"user":{}}`.
- 확신도: 하
- 위험도: 참고
