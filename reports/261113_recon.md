# 정찰 보고서 — 127.0.0.1 (2026-11-13)

- 대상: 127.0.0.1 (로컬 실습 환경)
- 수행 시각: 2026-11-13 19:34 ~ 19:36 KST
- 사용 도구: lab-tools `port_scan` 1회, `http_get` 4회 (한도 30회 중 4회 사용)
- 범위: 정찰만 수행. 로그인 시도, 페이로드 전송, 데이터 변경 요청 없음.
- 표기: 표시가 없는 문장은 응답에서 직접 관측한 사실이고, 추측에는 [추측]을 붙였다.

## 요약

- 1~10000번 포트 중 3000/tcp 하나만 열려 있고, 응답 제목으로 보아 OWASP Juice Shop이다.
- `/ftp`가 인증 없이 200을 돌려주고 제목이 `listing directory /ftp`인 디렉터리 목록 페이지다. 파일 목록 자체는 잘려서 못 봤다.
- **절차 3(자바스크립트에서 API 경로 찾기)은 수행하지 못했다.** 메인 페이지가 9984바이트인데 도구가 본문을 4000바이트에서 잘라서, 스크립트 태그가 있는 부분까지 보이지 않았다. 그래서 API 경로는 하나도 찾지 못했다.

## 1. 열린 포트와 서비스

`port_scan(target=127.0.0.1, ports=1-10000)`, nmap 7.99, `-sV`

| 포트 | 상태 | nmap 서비스 판정 | 실제 응답 |
|---|---|---|---|
| 3000/tcp | open | `ppp?` (인식 실패) | HTTP/1.1 200, HTML, `<title>OWASP Juice Shop</title>` |

- 나머지 9999개 포트는 closed.
- nmap은 서비스를 식별하지 못했지만 지문에 HTTP 응답이 그대로 들어 있다. HTTP 서비스가 맞다.
- nmap의 OPTIONS 프로브 응답: `HTTP/1.1 204 No Content`, `Access-Control-Allow-Methods: GET,HEAD,PUT,PATCH,POST,DELETE`
- 10001번 이상 포트는 스캔하지 않았다.
- 서버 소프트웨어와 버전을 알려주는 헤더(`Server`, `X-Powered-By`)는 응답에 없었다. Juice Shop 버전도 확인하지 못했다.

## 2. 발견한 경로와 상태 코드

| # | 경로 | 출처 | 상태 | Content-Type | Content-Length | 응답 형태 | 잘림 |
|---|---|---|---|---|---|---|---|
| 1 | `/robots.txt` | 절차 2 | 200 | text/plain | 28 | `User-agent: *` / `Disallow: /ftp` | 아니오 |
| 2 | `/` | 절차 2 | 200 | text/html | 9984 | Juice Shop 메인 HTML | **예** (4000바이트까지만) |
| 3 | `/ftp` | robots.txt | 200 | text/html | 11320 | `<title>listing directory /ftp</title>` 디렉터리 목록 페이지 | **예** (CSS 부분에서 끝남) |
| 4 | `/assets/public/favicon_js.ico` | 메인 페이지 `<link>` | 200 | image/x-icon | 15086 | 아이콘 바이너리 | 예 (내용 확인 불필요) |

요청하지 않은 것:

- `/#/jobs` — 모든 응답의 `X-Recruiting` 헤더에 적힌 값. `#` 뒤는 브라우저 안에서만 쓰이고 서버로 전송되지 않으므로 `/`와 같은 요청이 된다. 별도로 보내지 않았다.
- 메인 페이지에 보인 외부 주소(`fonts.googleapis.com`, `fonts.gstatic.com`, `www.youtube.com`) — 허용 범위 밖이라 건드리지 않았다.

### 공통 응답 헤더 (4개 응답 모두)

```
Access-Control-Allow-Origin: *
X-Content-Type-Options: nosniff
X-Frame-Options: SAMEORIGIN
Feature-Policy: payment 'self'
X-Recruiting: /#/jobs
```

- `Content-Security-Policy`, `Strict-Transport-Security` 헤더는 4개 응답 어디에도 없었다.
- `Set-Cookie`도 없었다.

### 절차 3: 자바스크립트 파일 — 수행 못 함

- 메인 페이지 본문이 **잘렸다.** 9984바이트 중 앞 4000바이트만 받았고, 그 구간은 `<head>`의 폰트·테마 CSS에서 끝난다.
- 받은 구간에 있는 `<script>`는 쿠키 동의 배너를 띄우는 인라인 스크립트 하나뿐이다. 외부 JS 파일을 불러오는 `<script src=...>` 태그는 보이지 않았다.
- 따라서 메인 페이지가 불러오는 JS 파일 이름을 알 수 없고, API 경로도 찾지 못했다.
- [추측] 스크립트 태그는 잘린 뒷부분(4000~9984바이트)에 있을 것이다.
- [추측] JS 파일 이름을 알아내더라도 번들 파일은 4000바이트보다 훨씬 클 것이므로 지금 도구로는 API 경로를 읽어내기 어렵다. IMPROVEMENTS.md 3번(필요한 것만 뽑는 도구)이 필요한 지점이다.

### 절차 4: 찾은 경로에 GET — 일부만 수행

- robots.txt와 메인 페이지 앞부분에서 나온 경로 2개(`/ftp`, favicon)에만 보냈다.
- API 경로는 찾지 못해서 보낸 것이 없다.

## 3. 의심 지점

### 3-1. `/ftp` 디렉터리 목록이 인증 없이 열려 있음 — 확신도: 상

- 근거(관측): 인증 정보 없이 보낸 GET에 200이 왔고, 제목이 `listing directory /ftp`다. robots.txt는 이 경로를 `Disallow`로 숨기려 하지만 접근을 막지는 않는다.
- 확인 못 한 것: 실제 파일 목록. 응답 11320바이트 중 앞 4000바이트가 전부 CSS여서 파일 이름이 하나도 보이지 않았다.
- [추측] 목록에 있는 파일도 인증 없이 내려받을 수 있을 것이다. 파일을 요청해 보지 않았으므로 확인된 사실이 아니다.

### 3-2. 모든 응답에 `Access-Control-Allow-Origin: *` — 확신도: 중

- 근거(관측): 4개 응답 모두에 이 헤더가 있다. nmap의 OPTIONS 프로브에는 `Access-Control-Allow-Methods: GET,HEAD,PUT,PATCH,POST,DELETE`가 왔다.
- [추측] 다른 출처의 웹 페이지가 이 서비스의 응답을 읽을 수 있다. 다만 `Access-Control-Allow-Credentials` 헤더는 관측되지 않았고, 인증이 필요한 API에서 어떻게 동작하는지는 확인하지 않았다. 실제 영향은 API 경로를 찾은 뒤에 판단할 수 있다.

### 3-3. `Content-Security-Policy` 헤더 없음 — 확신도: 하

- 근거(관측): 4개 응답에 CSP 헤더가 없다. 메인 페이지에 인라인 `<script>`가 있다.
- [추측] 스크립트 삽입이 가능한 지점이 있다면 브라우저가 막아주지 않는다. 삽입 가능한 지점이 있는지는 이번 정찰에서 확인하지 않았다. 헤더가 없다는 것만으로 취약점이 있다고 할 수는 없다.

### 3-4. 서비스 정체가 그대로 드러남 — 확신도: 상 (정보 노출 수준)

- 근거(관측): `<title>OWASP Juice Shop</title>`, HTML 주석의 저작권 표기, `X-Recruiting: /#/jobs` 헤더.
- [추측] Juice Shop은 학습용으로 일부러 취약하게 만든 애플리케이션이므로 알려진 취약 지점이 많을 것이다. 이번 정찰에서 응답으로 확인한 것은 위 3-1 ~ 3-3뿐이다.

## 4. 사람이 확인할 것

1. **메인 페이지의 스크립트 태그**: 브라우저에서 `view-source:http://127.0.0.1:3000/`을 열어 뒷부분의 `<script src=...>` 파일 이름을 확인한다. 파일 이름을 알려주면 그 경로로 정찰을 이어갈 수 있다.
2. **`/ftp`의 파일 목록**: 브라우저로 `http://127.0.0.1:3000/ftp`를 열어 어떤 파일이 있는지, 인증 없이 열리는지 확인한다.
3. **`/#/jobs`**: 헤더가 가리키는 화면이 실제로 있는지 브라우저에서 확인한다.
4. **10001번 이상 포트**: 필요하면 `1-65535` 범위로 다시 스캔할지 결정한다.
5. **JS 파일 이름을 추측해서 요청해도 되는지**: Angular 앱에서 흔한 이름(`main.js` 등)을 시도해 볼 수는 있지만, 응답에서 확인한 이름이 아니라서 이번에는 보내지 않았다. 허용 여부를 정해 달라.
6. **4000바이트 제한**: 메인 페이지, `/ftp`, JS 모두 핵심 내용이 잘린 뒤에 있다. IMPROVEMENTS.md 3번을 먼저 진행하면 이번에 못 한 절차 3, 4를 할 수 있다.
